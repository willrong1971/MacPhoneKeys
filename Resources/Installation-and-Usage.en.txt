VERSION 0.6.x CANDIDATE
Version 0.6.3 adds Start System Bluetooth Assistant… to direct builds.
When pairing is needed, use it before selecting the Mac in iPhone Bluetooth
settings and comparing both pairing codes. The helper may have no separate
window. Launch confirmation waits up to 10 seconds with no automatic retry;
the fallback pairing panel and Mac Bluetooth settings remain available.
Launching the helper does not establish pairing or visible phone text.
Steps requiring an app action must be requested before Tried, Still Not
Working is available. Choose Cannot Perform This Step if you cannot proceed,
or export early. Reaching the export page does not mean all steps were done.
Version 0.6.2 adds symptom-based troubleshooting under Connect iPhone… .
Choose an undiscoverable Mac, pairing failure or missing phone text, follow
the current step and report its result. Service recovery has a 30-second
cooldown. Input and unsent keys are cleared before system sleep.
Version 0.6.1 fixes creation of the public system pairing window.
Connect iPhone… opens a connection assistant with a public system pairing
panel, separate Mac preparation and keyboard-subscription evidence, and
user-confirmed phone text. New users see it on first launch; returning users
can open it from the menu bar menu.
Registration or advertising errors/timeouts allow at most two automatic
app-service recovery attempts. Waiting for a phone never triggers a restart
loop. Manual recovery changes only this app's service and retains pairing.
Export Diagnostics uses schema 2 with allowlisted state, requested actions,
skipped steps, exit reasons and fixed event summaries. Each record identifies
its current-guide, app-session or transport-instance scope. It excludes raw
logs, device names, addresses, identifiers, pairing codes, paths and input
content. Nothing is uploaded automatically.
Acceptance is performed by the current user alone. Historical 0.5.0 results
do not validate this candidate. The App Store sandbox candidate does not call
the system helper; it retains only the public pairing panel and settings.
App Store submission remains deferred, and sandbox pairing and typing are
unverified. This DMG is not an Apple-approved App Store release.
The direct build launches the helper through NSWorkspace after checking its
fixed system path, bundle identifier and system ownership. This helper path
is not an Apple-guaranteed stable public pairing API and may be unavailable
on another OS version; the fallback routes remain available.

Use a Mac keyboard to type on an iPhone over Bluetooth. The devices may use
different Apple IDs. No iPhone app is required.

The app stays in the menu bar without a Dock icon. Its unified phone-shaped
input key has a black body and white linework. Left-click it or press
Control + Option + K to toggle iPhone input. The white lines brighten only
after capture gains input focus; a dimmed icon means local Mac input.
The icon does not prove that text appeared on the phone.

The app's English name is MacPhoneKeys; its Chinese name is 手机键盘.
The build output path remains build/手机键盘.app in every interface language.

INTERFACE LANGUAGE
Standard macOS Bundle resources provide English (en), Simplified Chinese
(zh-Hans) and Traditional Chinese (zh-Hant). macOS selects a supported language
from the Mac's preferred language list; if none matches, the app uses English.
Change the Mac's preferred languages, or use this app's language setting in
System Settings > General > Language & Region > Applications if your macOS
version provides it. Settings and labels vary by macOS version.
Quit the app completely and reopen it after changing the language. The running
interface does not switch immediately. This setting does not change the
iPhone's input method or hardware-keyboard layout.

INSTALLATION
1. Open the MacPhoneKeys DMG you received. Read START-HERE.txt, then drag
   the app to Applications.
2. Open the app from Applications and allow Bluetooth access when prompted.
3. Eject the disk image after installation. Run only one copy of the app.

PAIRING AND TYPING
1. Open the Mac app. Its keyboard service starts automatically and its icon
   appears in the menu bar. The full settings window does not open by default.
2. If pairing is needed, open Connect iPhone… from the menu bar menu and
   follow the guide to start the system Bluetooth assistant. Then open
   Settings > Bluetooth on the iPhone, select your Mac's system name and
   compare both pairing codes. The name may differ from the app name.
   If the helper is unavailable, use the fallback pairing panel or Mac
   Bluetooth settings offered in the guide.
3. Open Notes or another text editor on the iPhone. Tap a text field so that
   the insertion cursor is visible. Use an English/US hardware-keyboard layout
   for the first literal English test.
4. Once connected, left-click the menu bar icon or press Control + Option + K.
   Wait for the icon’s white linework to brighten before typing. The input hint window is
   shown by default; you can turn it off in full settings.
5. Press Esc, press the shortcut again, click the icon again, or switch to
   another Mac window to stop relaying input and request key release.

If you use an external Bluetooth keyboard, keep it connected to the Mac.
It can supply the key events relayed by this app, just as the Mac's built-in
keyboard does.

MENU BAR AND FULL SETTINGS
Right-click the icon for “Start phone input” / “Stop phone input”,
“Full Settings…”, help and quit.
Full settings retains pairing, connection diagnostics, logs, English test text
and input-method controls. Show input hint window is enabled by default, and
your choice is saved. When turned off, input still works and only the menu
bar icon indicates its state. Esc, the shortcut again, or losing focus still
stops capture.
Start Typing in full settings follows the same hint-window setting.
Alternatively, click the original input area in full settings to capture
keystrokes there.
Full settings can stay closed during normal use. A shortcut or icon action
from another Mac app waits for the app to activate and gain keyboard focus
before capture begins. Cancellation or focus loss invalidates
pending activation; a late event cannot restart input.
If another program has claimed Control + Option + K, the app reports the
shortcut conflict. Use the icon or its menu to start and stop input instead.

In full settings, “Send English Test” asks for confirmation, then types
“mac keyboard test 123”
without pressing Return. “Send Test Text” confirms; “Cancel” cancels.
The accepted-key count can include queued reports. Check the iPhone's screen
to confirm that text actually arrived.

INPUT METHODS
The app sends physical key presses, not text composed by the Mac's input
method. The iPhone's hardware-keyboard layout and input method determine the
resulting text. In full settings, “Switch iPhone Input Method” sends
Control + Space; use the menu bar icon or global shortcut to start typing
again afterward. Chinese composition and other language
layouts remain unverified.
The current physical-key mapping follows an ANSI keyboard layout.

SIGNING AND FIRST LAUNCH
Source builds use ad-hoc signing by default and do not require your own
developer certificate. They are not automatically notarized. A historical
local test package used an Apple Development certificate, which is also not
the same as a notarized Developer ID distribution.
If macOS blocks a downloaded app, verify its source and follow the app-specific
Open Anyway option in Privacy & Security (Security & Privacy on older macOS).
Keep macOS security protections enabled. Details:
https://developer.apple.com/developer-id/

COMPATIBILITY AND LIMITS
Builds contain arm64 and x86_64 code with a macOS 12.0 deployment target.
This is a build target, not a guarantee that every Mac can act as a BLE keyboard.
The Mac must support the required Bluetooth peripheral operation.

Typing with version 0.2.0 has been confirmed on one Apple silicon Mac running macOS 26.6.2 and
one iPhone, including an app installed in Applications. Both its built-in
keyboard and a connected external Bluetooth keyboard have been used successfully.
Version 0.4.1 fixed activation and focus with full settings closed. The user
confirmed that the global shortcut started input in that workflow and the
complete abc123 string appeared on iPhone. Both pressing the shortcut again
and switching to another Mac window stopped capture and returned the icon to
its gray outline. In 0.5.0, the user also confirmed complete abc123 input with
both full settings and the hint turned off, normal icon and stop behavior,
and no hint window appearing.
Other Macs, iPhones, OS versions, USB keyboards, non-ANSI layouts, sleep/wake
reconnection and long-term reliability have not been comprehensively tested.
On the evening of November 2, 2026, the retained 0.6.2 installation recovered
after the system Bluetooth assistant was launched manually. The system
received NumericComparison and reported BLE pairing status 0. The user saw
complete abc123 output and a gray icon after stopping. Duplicate Mac entries
merged without intervention; no pairing records were removed and the keyboard
service was not rebuilt. This is a single 0.6.2 recovery result. Offline checks,
direct/sandbox Universal builds and Chinese/English offline UI checks passed
for 0.6.3. Version 0.6.3 was installed on November 3, 2026 and re-established
an encrypted keyboard subscription automatically. Visible phone text on this
version and long-term reconnection still need verification.

The BLE Battery service reports a fixed 100% test value, not the Mac's battery
level. Its PnP manufacturer field is an experimental placeholder.

TROUBLESHOOTING
If pairing or input fails, check that the app is running, its Bluetooth service
is started, and Bluetooth access is allowed. Confirm that a text field is
focused on the iPhone and its hardware-keyboard layout and input method match
the intended test.
If the app shows a connection but no text appears, open Connect iPhone… and
choose the connected-but-no-text symptom. Follow the guide for a new text
test. If it offers service recovery, request it once and wait for reconnection,
then check the result on the phone. Restarting only the app's service restored
output in one 0.4.1 test; the root cause was not determined, so do not repeatedly
restart it. Do not start by deleting pairing records or resetting global
Bluetooth settings.

No Dock icon or full window is expected by default. Find the app icon in
the Mac's menu bar and right-click it to open full settings or quit.
The input hint window is optional; check Show input hint window in full
settings if you want to see it during capture.

PRIVACY AND LOGS
Input is relayed only while capture is active and the app has keyboard focus;
the hint window is optional. The global shortcut toggles capture. The app does not request
Accessibility or Input Monitoring access. It does
not read Apple account data, contacts or the clipboard, and sends no input
through the internet or iCloud.
Logs contain connection events, errors and counts, not typed text. Location:
~/Library/Application Support/MacPhoneKeys/

Stopping capture discards reports still in the app's queue and attempts to
release held keys. Reports already accepted by the system cannot be recalled.

For bug reports, include OS versions, Mac architecture and reproduction steps.
Remove personal device names, Bluetooth addresses and account details from logs.

UNINSTALLATION
Quit from the menu bar icon's right-click menu, then move the app from
Applications to Trash. Bluetooth pairing
records are retained; remove the relevant Mac entry on the iPhone if desired.
