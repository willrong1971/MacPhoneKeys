### 2026-11-02 晚间诊断与 0.6.2 手动恢复

- 用户导出的 0.6.2 诊断显示权限允许、三项服务注册、广播中，但没有键盘订阅或读写事务，尚未形成输入通道。向导记录为 `pairingFailed / exportDiagnostics`，本 App 会话的公开配对面板为 `notOpened`。

- 保持原安装版 0.6.2 不变，手动启动系统自带 `BluetoothSetupAssistant` 后，系统实际收到数字比较（NumericComparison），BLE 配对状态为 0，随后建立键盘通道。用户确认 `abc123` 在手机完整显示，停止后图标恢复灰色。
- 手机上的两个 Mac 条目随后自行归一。本次未删除配对记录、未重建 App 键盘服务。上述事实支持此时恢复成功，不能证明今后每次重连、睡眠唤醒或其他设备都可靠。

### 0.6.3 (12) 候选变更与待验收项

- 直接安装版增加显式按钮，通过 `NSWorkspace` 启动固定系统路径的蓝牙助理；启动前检查路径、Bundle ID 和系统所有权。启动确认超时为 10 秒，不自动重试，不把启动成功当成配对或手机文字成功。保留公开配对面板及系统蓝牙设置备用入口。
- 系统助理路径不是 Apple 保证稳定的公开配对 API。App Store 沙盒构建明确不调用它，只保留公开面板与设置；商店继续暂缓，未完成沙盒实机验证。
- 向导要求先请求相应 App 动作，再允许“已尝试，仍不行”。无法执行和提前退出有独立记录；导出页不再声称全部步骤已执行。当前连接的新文字测试经用户确认后才记为完成。
- schema 2 诊断以白名单固定枚举记录启动状态、请求动作、跳过步骤、结束原因及作用域。向导记录属于 `currentGuide`，助理启动记录属于 `appSession`，传输计数属于 `transportInstance`；不导出原始日志、设备身份、配对码或输入内容。
- 本节记录源码与离线验证；本机安装的 0.6.2 保持原样，晚间手动恢复结果不转记给 0.6.3。
