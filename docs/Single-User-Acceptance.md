# 一人验收记录与计划

作者：九福爸爸 9fbaba。记录更新：2026-10-31。

本项目由当前用户一人验收，不以招募其他参与者为交付条件。测试通过只能说明表中实际设备和场景的结果；Universal 架构或最低 macOS 编译目标不等于其他设备已经通过。

## 已有版本证据

- 0.5.0 (8)：用户已验证关闭完整设置、关闭提示浮窗后的手机输入、快捷键停止和失焦停止。
- 2026-10-30：系统曾拒绝入站配对，日志显示没有处理配对请求的程序。App 服务重建与清除单个旧配对记录后仍失败。
- 后续系统配对助理接管数字比较，配对及加密键盘订阅成功；用户随后反馈“现在已经完全好了”。期间发生多项恢复操作，不能单独归因于其中一步。
- 上述结果来自原安装版，不能转用于 0.6.0 或沙盒构建。

## 0.6.x 候选版

当前工作正常的 `/Applications/手机键盘.app` 保留。候选版与安装版使用同一应用标识，真实蓝牙测试时只能运行一份；先退出另一份。离线预览使用独立标识和假传输，不发送到手机。

### 2026-10-31 配对入口修正

- 用户安装 0.6.0 后，公开配对控制器的 Swift 无参初始化路径未显示窗口，调用同秒返回失败；手机入站配对也记录到没有处理程序、状态 4815。没有证据表明有界恢复正在打断配对。
- 临时启动系统蓝牙设置助理后，用户确认两端出现配对码并连接成功，随后确认 `abc123` 完整显示且快捷键停止正常。本次未清除配对记录。
- 0.6.1 以 Objective-C 薄桥调用 Apple 文档指定的公开工厂。与真实 App 相同的应用身份、签名要求及 accessory 运行方式下，原生窗口实际显示，未选择设备，关闭后返回 `-1001`；窗口存续约 11.7 秒。该项证明窗口创建与取消路径，不能代替全新配对或沙盒输入验证。
- 0.6.1 (10) 已安装，并保留原配对自动重新建立加密输入订阅。用户在完整设置关闭、提示浮窗关闭的情况下，确认 `abc123` 完整显示，快捷键停止正常、图标恢复灰色；该项为更新后单独实测一次。
- 0.6.1 的 67 项连接状态测试、诊断返回码隐私检查、三语言资源检查及双架构构建通过；真实沙盒蓝牙与长期重连继续待测。

### 2026-10-30 离线与界面检查

- 三语言资源和 11 项隔离语言选择、10 项偏好、60 项焦点、170 项 BLE 生命周期、62 项连接证据与人工确认、180 项键码、21 项队列和 24 项 SDP 检查通过。
- 诊断隐私、无效字段、摘要长度上限，以及英文广播日志不得误报为订阅的回归检查通过。
- 两种构建均完成 arm64/x86_64 编译与严格签名检查。本地沙盒候选通过最小权限和隐私清单检查，仍无商店提交签名。
- 独立的中文离线预览完成向导、模拟测试与诊断实际保存；导出未包含设备标识、路径、原始日志或输入内容，未记为手机验证。
- 独立英文沙盒预览的向导布局及系统保存面板已观察；后续界面工具超时，未完成沙盒导出实际写入。该项继续待测。
- 离线预览未启动蓝牙，原安装版与其输入连接保留。真实配对、手机文字、重连和七天试用仍按上表记录。

首次全新配对需要改变当前配对关系，另行选择合适时间并由用户确认后进行；不为了凑次数反复清除工作正常的配对。未做的场景保持待测。

每次手机测试记录：实际 App 版本与构建方式、系统版本、操作、手机可见结果、恢复步骤、是否需清除配对。App 的发送计数、系统窗口成功、键盘订阅均不能代替手机可见结果。
